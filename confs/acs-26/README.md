# ACS-26 — Synthetic CFG-derived parse-tree benchmarks

## Headline result

At SEED=17, supervised parsing on the synthetic TEST_GRAMMAR1 dataset
matches/exceeds the hand-annotated hollow baseline:

| Metric | Hollow (reference) | Grammar 1 (synthetic) | Δ |
|---|---:|---:|---:|
| Parse F1 | 92.9% | **96.2%** | +3.3pp |
| Exact-match parses | 82.6% | **82.5%** | -0.1pp |
| Step-pick | 99.2% | **99.6%** | +0.4pp |
| From-scratch gram | 100% | 100% | 0 |

This validates the binarization convention encoded in
``util.cfg.generate_with_merges``: right-binary inside NP/PP/AdjP,
flatten VP at the parent level, left-incremental at the S level.
With these rules the synthetic gold brackets equal what
human annotators chose intuitively.

## Grammar 3 — also matches hollow

| Metric | Grammar 3 (fixed) |
|---|---:|
| Parse F1 | **91.2%** |
| Exact-match parses | **70.0%** |
| Step-pick | **97.3%** |
| From-scratch gram | 100% |

TEST_GRAMMAR3 had two real defects that made earlier runs look bad:

1. **Intransitive `VP → V` allowed** even though every verb in the
   lexicon (saw / liked / chased / carried / read / admired) is
   transitive in English. This produced sentences like
   ``the apple liked`` or RelClauses like ``which chased`` standing
   alone — semantically nonsense AND confusing for the parser
   because it had to learn TWO conventions for the same (V) token
   (sometimes a complete VP, sometimes an incomplete one).
2. **No `VP → V NP PP` production** (TEST_GRAMMAR1 has it) — limited
   structural variety and forced PP-attachment only at the
   prepositional-phrase boundary, never as a verb modifier.

Fix (in [util/cfg.py:177](../../src/util/cfg.py)):
```python
"VP": [["V", "NP"], ["V", "NP", "PP"], ["V", "PP"]],  # all transitive
```

After fixing: F1 jumped 66.4 → **91.2%**, step-pick 77.1 → **97.3%**,
gen-grammatical 50-95% → **100%**. Generation novelty also rose
(46-67% gram-novel per learning-curve step).

The 5-seed sweep on the fixed grammar: F1 = 85.8 ± 5.4pp,
best 91.2% (seed=13), worst 76.8% (seed=100). The 12.6pp EM gap to
hollow (70.0 vs 82.6) is the residual RelClause attachment-ambiguity
cost — the only remaining hard case for greedy unsupervised parsing.

---


This conf runs the full ``hollow_learn_test_mh`` pipeline plus the
new ``learning_curves_test`` against two synthetic, CFG-derived parse
corpora:

| Grammar | Dataset | Output folder |
|---|---|---|
| ``TEST_GRAMMAR_SMALL`` (S→NP VP; VP=V (NP); 4 N, 4 V, 2 Det) | ``data/cfg_grammar_small/`` (200) | ``confs/acs-26/grammar_small/`` |
| ``TEST_GRAMMAR_MED`` (+ AdjP, PP, V NP PP) | ``data/cfg_grammar_med/`` (200) | ``confs/acs-26/grammar_med/`` |
| ``TEST_GRAMMAR_LARGE`` (+ RelClause, RelPro) | ``data/cfg_grammar_large/`` (400) | ``confs/acs-26/grammar_large/`` |

Both datasets are produced by ``scripts/generate_cfg_dataset.py``
which calls ``util.cfg.generate_with_merges`` — the merges come
directly from the CFG derivation tree (left-binarized), so the gold
brackets match the grammar exactly.

## Running

```bash
python confs/acs-26/run_grammar_small.py
python confs/acs-26/run_grammar_med.py
python confs/acs-26/run_grammar_large.py
```

Each conf script calls:

1. ``run_hollow_learn(corpus_dir, out_dir, grammar, corpus, ...)`` — the
   full pipeline (parse F1, step-pick, chunk-class probe, from-scratch
   generation, masked completion, gold-vs-non-gold histograms,
   six-panel summary).
2. ``run_learning_curves(corpus_dir, out_dir, ...)`` — incremental
   training (one sentence at a time), eval every 10 train sentences,
   logged into ``learning_curves.csv`` + ``learning_curves.png``
   (parse accuracy / generation grammaticality / generation novelty).

## What's new vs. hollow_learn_test_mh

- **``data/cfg_grammar_{small,med,large}/``** — CFG-derived
  ground-truth (no hand annotation), generated by
  ``scripts/generate_cfg_dataset.py``.
- **``step_pick_histograms.png``** — gold vs non-gold candidate density
  per heuristic, with Cohen's d effect-size label. Tells you *which*
  parse-time score actually separates the two populations.
- **``learning_curves.png``** — parse F1, gen grammaticality, gen novelty
  every 10 training sentences. Tracks data-efficiency.

## Reproducibility

All scripts seed ``random``, ``numpy``, AND the C++ cobweb RNG
(``cobweb.set_random_seed``) with ``SEED=13``. Set
``PYTHONHASHSEED=0`` in your environment for fully reproducible runs:

```bash
PYTHONHASHSEED=0 python confs/acs-26/run_grammar_med.py
```
