# Pilot B (digit span, DD): summary of findings (2026-11-21)

Script: experiments/v3/psych_digits.py. Learner: paper config C3 (posterior storage, window 7, story_facet dropped), cfg recorded in every JSON.
Arms: `rule/*` = the plan (groups chosen by the chess recognition rule, THETA 16); `forced34/*`, `forced3/on`, `forced4/on` = DIAGNOSTIC arms
(groups imposed, recognition test bypassed, everything else as the plan). Decode rules idon / idoff are scored on one trajectory.
Prior arms: off / on (N_pre = 768 draws for seed 13) / x10. Lists = 40 random digits (39 for forced3), no staircase.
Exposure axis = cumulative learned encoding units (groups plus ungrouped 4-digit pieces); p windows = (n/2, n].

## Result 1 (plan rule): no group is ever recognised (R3, permanent)
Across rule/off, rule/on, rule/x10 (3 seeds, 5-6k units each, 0 groups recognised in total) the best recognition bits of any 3- or 4-digit
prefix are 4-12 (THETA 16). Every digit goes to STM, so span stays at K = 7 whatever the decode rule. Diagnostic probes: bits of stored
prior-stream strings mean -2.9 (max 1.7); a probe string learned 100 times amid random pieces still scores -2 to -11 content bits.
Cause: with C3 the content description of a composite is made of the donated concept-id bags of its parts' contexts (L, LC, R, RC), which
differ between the stored record and the same string re-parsed (and between occurrences), so the content concept does not identify a repeated
digit string; the context bits are the same constant for every isolated group (about 5 bits: all slots read BOS/EOS), so the context
hierarchy carries nothing (R4). Recognition by the chess rule therefore cannot fire on this learner without a change to the learner or the rule.

## Result 2 (diagnostic, groups imposed): decode accuracy against exposure
See tables. Identity decode saturates 3-digit groups (p(3) .995 at 15k units, forced34) while 4-digit groups lag (.41-.44), so the 4 > 3 error
ordering (effect 13, G2) holds. Label-only decode (identity off) is far weaker (p(all) .22-.34 at 15k).
- forced3, identity on: p(3) .976 at 5k units, .999 at 10k: the R1 explosion. Projected staircase span reaches 20 / 40 / 80 / 104 at sessions
  ~100-104 / 117-121 / 127-132 / 129-134, i.e. 4-5x too fast and the 80 -> 104 stretch lasts ~2 sessions (G3 fails: 80 before session 250).
- forced34 (3 or 4 at random, 52% 3-digit): p(all) .71-.73 at 15k (idon), projected span ~7 (7.1-7.5) at 15k units; never reaches 20 within the
  measured range, i.e. R2 (stall) for the mixed-size groups: 4-digit coverage (10^4 strings) limits p, as the plan predicted.
- forced4: p(4) .68 (idon), .13 (idoff) at 15k; span ~7.
- Prior x10 raises p early (p(all) .48 at 500 units vs .08 for prior off, idon) and saturates 3-digit groups earlier; x10 runs stopped at
  5.9k / 7.6k / 11.1k units (time, cancelled), so only checkpoints up to 5k are 3-seed.
- Prior on vs off differ little for identity-off after 5k units.
The projected spans assume list length tracks the projected span and use p measured on 40-digit lists with imposed group mixes; they are
projections, not staircase runs.

Caveats: p(3) for forced34 idoff has a wide seed range (.17-.67 at 15k); stored-chunk identity uses summed posterior weight >= 0.5
(share at .25 / 1.0 is logged per list as stb25_*, stb100_*).
